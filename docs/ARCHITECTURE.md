The normal path for a system operation is a Vue view calling `desktop`, a Tauri command validating the request and coordinating shared state, then a Rust crate carrying out the operation. Keep Windows paths, registry access, process control, and file mutations in Rust. Update both sides of the command contract and their tests when changing a payload or an error code.

## Installation, diagnostics, and launch

1. Setup scans the selected folder automatically. Startup scans the saved installation, including when the interface reopens after the game exits. The backend inspects the executable and resources in read-only mode, evaluates diagnostics, emits scan progress, and saves the folder in preferences after recognition. The scanner accepts both the usual local drive path and the canonical local drive path held by the installation lease during launch and post-mod verification. The Diagnostics page displays the latest report and allows an optional refresh and export.
2. **Play** calls `start_game` to get a fresh diagnosis even if the previous report showed a launch blocker. The backend takes the operation and installation locks and checks that the game is closed. It sends the new report to the interface, reconciles eligible managed graphics files, then evaluates launch readiness. It synchronizes the language and validates the active mod runtime before starting `Game.exe`.
3. [lifecycle.rs](../src-tauri/src/lifecycle.rs) waits for the supervised game's visible window before destroying the launcher WebView. The Rust backend stays alive, including SaveGuard when enabled. On exit, Arachnid recreates the interface. If the game exits before displaying a window, the interface stays available.
4. Launch status and crash advice are returned to the UI. The advice for the recognized graphics crash depends on which graphics mods were active and points to ReShade first when it was enabled.

Recognition, launch eligibility, and mod compatibility are separate checks. Diagnostics show a local Direct3D wrapper that could not be verified and include its fingerprint in the exported report when readable. Use [game_build.rs](../crates/arachnid-core/src/game_build.rs), [readiness.rs](../crates/arachnid-core/src/readiness.rs), and the launch tests when working on build support.

## Settings and language

After Setup and on startup, Arachnid initializes missing native display and graphics values for a recognized, supported game. The fallback for a new Windows profile is 1920 × 1080 in fullscreen with the Medium preset. Existing registry values are preserved. Initialization has its own transaction journal, and interrupted writes can be reviewed and restored in Graphics. Language synchronization and default mods run afterward.

[GraphicsView.vue](../src/views/GraphicsView.vue) keeps edits as a local draft. **Apply changes** prepares and applies a checked plan, then refreshes the displayed state. [draftNavigation.ts](../src/composables/draftNavigation.ts) handles leaving a page with unapplied changes. Preset definitions and supported settings live in [arachnid-settings](../crates/arachnid-settings). The original presets are Very Low, Low, Medium, High, and Amazing. Manual edits can produce a Custom configuration.

[GameLanguageControl.vue](../src/components/game/GameLanguageControl.vue) exposes one preference for the UI and game on Home and during Setup. [i18n.ts](../src/composables/i18n.ts) resolves the device locale in Automatic mode. English is the interface fallback. [languages.rs](../crates/arachnid-settings/src/languages.rs) handles the game's `Install/Language` value and checks the language resources in `Data`. Game changes are deferred while it runs. If neither the requested nor English resource is found, the game keeps its stored language.

## Mods and recovery

- [ModsView.vue](../src/views/ModsView.vue) keeps graphics selections and the costume choice in a draft. Apply scans the installation and refreshes the managed mod state before preparing any writes. It skips selections already in effect, then checks the installed files and selections again after applying. A managed graphics DLL already back at its recorded original state can be reinstalled from verified resources or left as is when deactivating. For an unexpected change to an owned DLL, explicit Apply verifies the original backup, captures the observed file for rollback, and writes the requested final state directly. This avoids a temporary reset in the game directory. A conflicting file without recorded ownership remains blocked. Graphics mods and costumes use separate transactions, so an error in one can follow a successful change in the other.
- [composition.rs](../crates/arachnid-mods/src/composition.rs) models the eight combinations of Fix Enhancers, ReShade, and DXVK, including all off. On startup and after Setup, the app attempts to apply Fix Enhancers on a compatible installation with no previous graphics mod transaction. It verifies the payload and uses the same journal and file guards as manual changes. [performance.rs](../crates/arachnid-mods/src/performance.rs) defines prepared recipes, and [mods.rs](../src-tauri/src/mods.rs) connects them to the launch runtime. ReShade uses Direct3D 9 without DXVK and a per-session Vulkan layer with DXVK.
- [skins.rs](../crates/arachnid-mods/src/skins.rs) manages the optional texture packs. Some replace the base suit and others target a different suit in the wardrobe. **Original textures** removes the Arachnid-managed costume change.
- [arachnid-repair](../crates/arachnid-repair) supplies the common transaction machinery. A prepared plan identifies the intended changes and their expected starting state. Applying rechecks the digest and current state, preserves the originals, and records recovery information. Startup, Play, and opening Mods can reconcile changed or missing managed graphics files to the last committed mod combination. The transaction verifies the recorded originals and computes the requested result from that baseline, preserving the observed bytes for rollback. The same mechanism uses the player's new selection during explicit Apply. Unmanaged files are protected and unfinished transactions still require explicit recovery. Deactivation restores the pre-mod state, which can include an existing wrapper. If the Fix configuration already matches its original state or was originally absent and is already gone, deactivation leaves it as is and checks it again before touching the binaries.

## SaveGuard

[saves.rs](../src-tauri/src/saves.rs) wires SaveGuard to desktop commands and the background watcher. [discovery.rs](../crates/arachnid-saveguard/src/discovery.rs) looks for known save locations using the installation and files it finds. Settings provides a manual source override.

The [SaveGuard crate](../crates/arachnid-saveguard/src/lib.rs) checks stable file contents before copying. Automatic backups group changes into fixed five-minute windows. Later changes update that window's backup without extending the deadline. Manual and pinned snapshots have their own lifecycle.

The default storage quota is 1 GiB (1024 MiB); startup upgrades profiles using the previous 256 MiB default while preserving other configured quotas. Save groups support up to 32 files of 1 MiB each, including in-game photos. At the copy-count limit, the oldest unpinned snapshots are removed. Under storage pressure, previously deleted copies are reclaimed first (their deletion can then no longer be undone). SaveGuard first verifies that enough eligible old copies can be removed, stages and verifies the new contents, then removes those copies before publication. Pinned copies and the latest complete snapshot are preserved; if these protections prevent freeing enough space, the operation reports the quota limit without deleting history. Restore journals support both generations of a full save group.

Restore checks the snapshot, preserves the current state for rollback, and requires the game to be stopped before applying an approved plan. Test that a restored save actually loads when changing this workflow. A matching hash verifies the copied bytes.

## Launcher updates

[updates.rs](../src-tauri/src/updates.rs) checks the configured GitHub release manifest in Rust and offers stable versions newer than the running launcher. The UI asks before downloading and displays progress. Tauri verifies the installer signature and its signed version. The backend checks for a running game before and after downloading and takes the shared operation lock before starting the installer. Starting the game through Arachnid is blocked during the update. [The release workflow](../.github/workflows/release.yml) configures signed builds with the public key and update feed.

## Local data

Tauri resolves the app's directory under Windows Local AppData. [storage.rs](../src-tauri/src/storage.rs) manages `preferences.json` and `launcher.log`. SaveGuard keeps its profile in `saveguard-profile.json` and stores snapshots in `saveguard/` under the app data directory, outside the save source. The diagnostics report is exported to a destination chosen by the player.
